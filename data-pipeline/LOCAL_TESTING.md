# Local testing — pipeline Lambdas

Three ways to run the pipeline locally, cheapest first.

## 0. Unit tests (no infra)
```bash
pnpm --filter data-pipeline test
```

## 1. Local infra (Postgres + MinIO)
Use the root `docker-compose.yml` — it has Postgres, MinIO, and both buckets
(`mna-files`, `mbox-archive`) already configured:
```bash
# From repo root
docker compose up -d
```
- **Postgres** on host `:5440`
- **MinIO** on `:9000` (API) / `:9001` (console)
- Buckets `mna-files` + `mbox-archive` auto-created on first start

Apply the schema (from repo root):
```bash
pnpm db:migrate
```

## 2a. Fast path — invoke handlers directly (tsx, no Docker-for-Lambda)
Runs the TypeScript handler against local Postgres/MinIO using `.env.local`:
```bash
pnpm --filter data-pipeline invoke crmIngest '{"limit":50}'
pnpm --filter data-pipeline invoke vaultParse '{"limit":2}'
```
Good for logic + DB integration. Does NOT validate the Lambda bundle/runtime.

## 2b. Real Lambda runtime — SAM CLI
Validates the actual bundle inside the Lambda Docker image (catches missing
deps, `/tmp` limits, memory pressure, cold start).

**Prereqs:** Docker running (root `docker compose up -d`), `sam` installed (`pip install aws-sam-cli`).

```bash
# 1. Build bundles
pnpm --filter data-pipeline build

# 2. Copy secrets template (gitignored) — fill in ANTHROPIC + GOOGLE creds
cp data-pipeline/sam-env.example.json data-pipeline/sam-env.docker.json

# 3. Invoke — shortcut auto-generates the event file
pnpm --filter data-pipeline sam <FunctionName>
```

Available function names: `CrmIngest`, `CrmLlmSubmit`, `CrmLlmFetch`,
`CrmDomainClassify`, `VaultParse`, `VaultArchiveStart`, `VaultArchivePoll`

SAM reaches Postgres/MinIO via `host.docker.internal` (the `--add-host` flag
is baked into the `pnpm sam` shortcut). Credentials live in `template.local.yaml`
(gitignored — generated by copying and filling `sam-env.example.json`).

## Pipeline test sequence (full end-to-end)

```bash
pnpm sam VaultArchiveStart      # creates Vault export → vault_exports row
pnpm sam VaultArchivePoll       # poll until COMPLETED → mbox.gz → S3 → mbox_files
pnpm sam VaultParse             # parse mbox → raw_emails
pnpm sam CrmDomainClassify      # classify domains
# For LLM steps, use sync mode (tiny + real-time, not batch):
echo '{"limit":3,"mode":"sync"}' > /tmp/event-sync.json
sam local invoke CrmLlmSubmit --template data-pipeline/template.local.yaml \
  --event /tmp/event-sync.json --add-host host.docker.internal:host-gateway
pnpm sam CrmIngest              # ingest → public.* + refresh marts
```

## What's testable where

| Stage | Fast path (2a) | SAM (2b) | External dep |
|---|---|---|---|
| crmIngest | ✅ | ✅ | none (pure DB) |
| vaultParse | ✅ | ✅ | mbox `.gz` in MinIO + `mbox_files` row |
| crmLlmSubmit/Fetch/DomainClassify | ✅ | ✅ | real Anthropic (use `mode:"sync"` + small limit) |
| vaultArchiveStart/Poll | ⚠️ | ⚠️ | real Google Vault |

## Teardown
```bash
docker compose down      # keep volumes
docker compose down -v   # wipe Postgres + MinIO data
```

## Notes
- Local uses password auth + env vars — does NOT exercise AWS SSM / RDS-IAM.
  A staging `terraform apply` + invoke is needed to prove those paths.
- `dist/`, `sam-env.docker.json`, `template.local.yaml`, `.aws-sam/` are gitignored.
